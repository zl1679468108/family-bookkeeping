# 2026-05-29 工作日志

## 分类排序功能重构

**改动文件：**
- `frontend/src/pages/Categories.tsx` - 重构排序交互逻辑
- `frontend/src/pages/Categories.scss` - 新增排序模式样式

**改动内容：**
- 将原有"随时拖拽即保存"的排序方式改为"按钮控制的排序模式"
- 新增 `sortingMode` 状态控制排序模式的开启/关闭
- 新增 `originalList` 状态用于取消排序时恢复原始顺序
- 普通模式下卡片不可拖拽，显示编辑/删除按钮
- 点击「编辑排序」按钮进入排序模式：卡片变为可拖拽，显示拖拽手柄图标和"可拖拽"标签，隐藏编辑/删除按钮
- 排序模式下拖拽仅前端调整顺序，不发送请求
- 点击「完成排序」统一调用 `reorderCategories` API 批量提交排序结果，成功后退出排序模式
- 点击「取消」恢复原始排序并退出排序模式
- 排序模式中切换 Tab 自动取消排序
- 排序模式下卡片视觉变化：虚线边框、琥珀色背景、grab 光标
- **Bug修复**：修复 useEffect 无限循环 — `filteredCategories` 每次渲染生成新数组引用导致 setState 无限重渲染。通过 `useMemo` 稳定引用 + `useRef` 比对 ID 序列解决。
- **重构**：`transactions.category` 和 `budgets.category` 从 VARCHAR(名称) 改为 UUID(关联 categories.id)：
  - 数据库：`database-init.sql` 列类型改为 UUID + 外键 + 迁移 SQL
  - 后端 statistics.service.ts：CategoryBreakdownItem 新增 `category_id`/`category_name`/`category_icon`，JOIN categories 获取名称
  - 后端 budgets.service.ts：BudgetCategoryStatus/BudgetAlert 同样新增三字段 + loadCategoryInfo 方法
  - 后端 export.service.ts：loadCategoryMap 改为按 UUID 索引
  - 前端 useCategories.ts：重写，移除 LEGACY_MAP/getCategoryKey，改为 ID-based lookup；新增 getCategoryId() 用于 OCR 转换
  - 前端 types/：statistics/budget/map 类型同步更新
  - 前端 pages：Budgets/Dashboard/Map/Reports 适配新字段；AddTransaction OCR 转 UUID
  - 前端 components：FilterBar/ChartCard/CategoryRanking 适配；ImageUploader 返回 categoryName
  - 前端 utils：categoryColors 改为动态哈希；commonDic 移除硬编码分类列表
  - 数据库：`user_id` 改为 NOT NULL，删除 16 个全局默认分类
  - 后端 `auth.service.ts`：注册时自动创建 2 个默认分类（购物🛒 + 工资💼）
  - 后端 `categories.service.ts`：查询只按 `user_id` 过滤；`findAll` 对无分类的老用户自动创建默认分类；`reorder` 恢复 `user_id` 过滤
  - SQL：`TRUNCATE TABLE categories;` 清空旧数据后，后端自动为每次查询的用户补建默认分类
- **Bug修复**：后端 `categories.reorder()` 无法更新默认分类排序 — 更新条件中 `.eq('user_id', userId)` 对 `user_id = NULL` 的默认分类永远不匹配，导致排序写入静默失败。移除 `user_id` 过滤条件（排序操作对用户可见的所有分类均有效）。
