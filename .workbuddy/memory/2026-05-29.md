## LocationPicker 竞态修复：visible effect 与 complete callback 互斥

## LocationPicker 状态管理重构：mapReady 持久化 + visibleRef 闭包安全

**问题1：** `completeDone` 被每次弹窗打开重置为 false，但 `map.on('complete')` 只注册一次 → 第二次打开弹窗时 visible effect 永远等不到 `completeDone=true` → 不定位。

**问题2：** `handleMapCreated` 的 useCallback 闭包捕获了创建时的 `visible` 值（始终为 false），complete 回调在 visible 变化后触发时读到的是旧值 → 不执行定位。

**修复：**
- `completeDone` 改名为 `mapReady`：持久状态，不在弹窗打开时重置。complete 只触发一次，mapReady 永远为 true 后不变
- `initDone`：临时状态，每次弹窗打开重置，标记本次弹窗是否已完成初始化
- 新增 `visibleRef = useRef(visible)`：渲染时始终同步最新 visible 值，complete 回调通过 `visibleRef.current` 读取（打破闭包陷阱）
- 两条路径互斥保证：visible effect 检查 `mapReady.current`；complete callback 检查 `initDone.current && visibleRef.current`

**最终流程（三条路径均正确）：**

| 场景 | visible effect | complete callback | 结果 |
|------|---------------|-------------------|------|
| 弹窗在 complete 之后打开 | mapReady=true → doLocate | visibleRef=false → skip | ✅ |
| 弹窗在 complete 之前打开 | mapReady=false → skip | visibleRef=true → doLocate | ✅ |
| 第二次打开弹窗 | mapReady=true → doLocate | 已注册，mapReady 守卫跳过 | ✅ |
