## AMap 地图实例池化重构

### 背景
MapCanvas 和 LocationPicker 两个组件每次切换页面/弹窗时都会销毁重建地图实例，导致重复加载 SDK + 请求瓦片，产生明显延迟。

### 方案
实现三层的实例池化架构，用类管理地图全部逻辑：

| 层 | 文件 | 职责 |
|---|---|---|
| SDK 单例 | `services/amapService.ts` (新) | 加载高德 JS SDK 一次，并发去重 |
| 实例池 | `services/mapInstancePool.ts` (新) | DOM 转移而非销毁，keep-alive |
| React Hook | `hooks/useMapInstance.ts` (新) | acquire/release + ResizeObserver |

核心机制：地图的容器 div 由池管理（纯 DOM，不受 React 生命周期控制），释放时移到 body 隐藏区域，再次获取时移回组件容器 + resize()。

### 改动文件（5 个）
- **新建** 3 个：amapService.ts, mapInstancePool.ts, useMapInstance.ts
- **重构** 2 个：MapCanvas/index.tsx, LocationPicker/index.tsx（脱离 @uiw/react-amap，改用原生 AMap API）

### QA 结果
- TypeScript 编译：零错误
- 核心池化逻辑：正确
- 发现 1 个 InfoWindow 未清理问题 → 已修复
- 2 个低优先级观察：options 不重新应用、setTimeout 不可取消

## MapCanvas 瓦片仍请求问题修复 (01:55)

**问题**：LocationPicker 池化效果明显，MapCanvas 切换页面仍有瓦片请求。

**根因**：`release()` 时调了 `map.resize()`，地图被移到 800×600 的 poolHost 后强制重新计算视口 → 瓦片按 800×600 加载。`acquire()` 时又 resize 一次 → 瓦片按实际尺寸重新加载。两次 resize 产生不同视口范围 → 缓存未命中。

**修复**（`mapInstancePool.ts`）：
1. `release()`: 去掉 `setTimeout(resize, 100ms)` — 地图保持已知视口状态，不感知 poolHost 尺寸变化
2. `acquire()` 复用路径: `setTimeout(50ms)` → `double rAF` — 确保浏览器 layout 稳定后再 resize

## 架构合并 + 瓦片取消修复 (10:00)

**用户反馈**：MapCanvas 来回切换仍有大量 cancelled 瓦片请求。

**根因分析**：
- `acquire()` resize + `ResizeObserver` resize + `fit` effect setBounds 三个操作连续触发
- 每次 resize/setBounds 都会取消上一批未完成的瓦片请求
- 同时 `AmapService` + `MapInstancePool` 两个类有冗余

**修复**：
1. 合并 `amapService.ts` + `mapInstancePool.ts` → `amapManager.ts`（单类管理 SDK + 池）
2. `acquire()` 不再调用 `resize()` — 由 ResizeObserver 单独负责
3. ResizeObserver 防抖从 200ms → 300ms
4. 组件中 `(window as any).AMap` 全部替换为 `AmapManager.getInstance().AMap`
5. 删除旧文件 amapService.ts 和 mapInstancePool.ts

**最终文件**：
- `services/amapManager.ts` (新) — 合并类，SDK加载 + 实例池化
- `hooks/useMapInstance.ts` (重写) — 简化，统一用 AmapManager
- `components/MapCanvas/index.tsx` (更新) — AmapManager 替换 window.AMap
- `components/LocationPicker/index.tsx` (更新) — 同上

## MapCanvas 瓦片取消最终修复 (10:15)

**根因**：ResizeObserver 的 debounce(300ms) resize 和 fit effect 的 setBounds 是两个独立、异步的触发源。ResizeObserver 在 `.observe()` 时立即触发，但 resize 被 debounce 推迟 300ms。300ms 后 resize 时，fit 的 setBounds 瓦片正在加载 → resize 取消它们重新加载。

**时序问题**：
```
setReady → ResizeObserver fire → 300ms timer start
    ↓
react-query data arrives → fit setBounds → 🔵 tiles loading
    ↓ (300ms later)
ResizeObserver resize() → 🔴 cancels fit tiles → reloads
```

**修复**：
1. MapCanvas 设置 `skipResizeObserver: true` → 去掉独立的异步 resize 触发源
2. 在 fit effect 中，resize + setBounds 写在同一同步块 → 合并为一次瓦片触发
3. 在 locate effect 中同理，resize + setCenter/setZoom 合并
4. LocationPicker 保留 ResizeObserver（不受数据驱动，没有 fit 竞争）
