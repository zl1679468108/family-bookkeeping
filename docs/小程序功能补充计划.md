# 小程序功能补充计划

## 一、计划概述

本计划针对小程序端（Taro）相对于 PC 端（React）缺失的功能进行补充，以实现两端功能对齐。

## 二、功能差异分析总结

### 2.1 登录模块差异

| 序号 | 功能点 | PC端状态 | 小程序端状态 | 优先级 |
|-----|-------|---------|------------|-------|
| 1 | 登录页图形验证码 | ✅ 有 | ❌ 无 | 🔴 高 |
| 2 | 登录成功返回来源页 | ✅ 有 | ❌ 无 | 🔴 高 |
| 3 | 忘记密码步骤指示器 | ✅ 有 | ❌ 无 | 🟡 中 |
| 4 | 忘记密码成功页面 | ✅ 有 | ❌ 无 | 🟡 中 |

### 2.2 其他模块差异（优先级排序）

| 序号 | 功能点 | 优先级 |
|-----|-------|-------|
| 1 | 报表页增强（多时间范围+分类饼图+成员对比） | 🔴 高 |
| 2 | 交易列表增强（搜索+分类筛选+详情页） | 🔴 高 |
| 3 | 记一笔集成模板选择 | 🔴 高 |
| 4 | 首页预算进度卡片 | 🟡 中 |
| 5 | 交易图片大图预览 | 🟡 中 |
| 6 | 年度报告长图保存分享 | 🟡 中 |

## 三、执行计划

### 阶段一：登录模块补充（预计 1-2 天）

#### 任务 1：登录页接入图形验证码
- **文件**：`taro/src/pages/User/Login/index.tsx`
- **依赖**：后端接口 `GET /api/auth/captcha` 已存在
- **内容**：
  1. 添加 captchaId、captchaCode、captchaSvg 状态
  2. 实现 refreshCaptcha 函数
  3. 登录成功后刷新验证码
  4. 修改 signIn 调用参数

#### 任务 2：登录成功返回来源页
- **文件**：`taro/src/pages/User/Login/index.tsx`
- **内容**：
  1. 登录成功前获取页面栈
  2. 判断是否有来源页
  3. 有来源页则返回，无则跳转首页

#### 任务 3：忘记密码步骤指示器
- **文件**：`taro/src/pages/User/ForgotPassword/index.tsx`
- **内容**：
  1. 添加步骤状态（email/code/success）
  2. 添加步骤指示器组件
  3. 添加成功页面

### 阶段二：核心功能补充（预计 3-4 天）

## 四、依赖检查

### 后端接口（已存在，可直接调用）

| 接口 | 方法 | 用途 |
|-----|------|-----|
| `/api/auth/captcha` | GET | 获取验证码 |
| `/api/auth/login` | POST | 用户登录（支持验证码） |
| `/api/statistics/summary` | GET | 汇总统计 |
| `/api/statistics/monthly-trend` | GET | 月度趋势 |
| `/api/statistics/category-breakdown` | GET | 分类占比 |
| `/api/statistics/daily-summary` | GET | 每日汇总 |
| `/api/statistics/yoy-comparison` | GET | 年度对比 |
| `/api/members/comparison` | GET | 成员对比 |
| `/api/reports/annual` | GET | 年度报告 |
| `/api/export/excel` | GET | 导出 Excel |
| `/api/templates` | GET | 获取模板列表 |
| `/api/templates/:id/execute` | POST | 应用模板 |
| `/api/budgets/status` | GET | 预算状态 |

## 五、风险评估

| 风险点 | 描述 | 应对措施 |
|-------|------|---------|
| 验证码 SVG 渲染 | 小程序 SVG 渲染可能有兼容性问题 | 备选方案：使用 Canvas 绘制验证码 |
| 页面栈获取 | 页面栈为空时的边界处理 | 添加空栈判断，默认跳转首页 |
| 图片预览性能 | 多图预览可能卡顿 | 限制预览图片数量，懒加载 |
| Canvas 绘制性能 | 年度报告长图绘制可能耗时 | 添加 loading 状态，优化绘制逻辑 |
