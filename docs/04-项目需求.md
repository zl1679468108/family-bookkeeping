# 产品需求池

> **版本**：v1.0 | **日期**：2026-05-31 | **目标**：PC 端首发，后续 H5 同步

## P1 — 本迭代（PC 端）

### P1-1 现金流日历 `PC`

**定位**：PC 端日历视图，直观展示每日收支全貌。

**痛点**：现有报表只有折线/饼图，看不到"具体哪天花了多少"的颗粒度。PC 大屏天然适合日历布局。

**核心功能**：

| 功能 | 描述 |
|------|------|
| 日历月视图 | 当月日历网格，每格显示日期 + 当日支出(红)/收入(绿)合计 |
| 周视图 | 单周横向展开，每日支出 Top 3 分类显示 |
| 日视图 | 选中日期展开当日交易明细列表（时间、分类、金额、备注） |
| 月度汇总 | 日历下方卡片：本月日均支出、最高消费日、最低消费日、支出天数占比 |
| 跳转联动 | 点击日期可跳转到交易记录页并自动筛选该日 |

**技术边界**：
- **不新增数据库表**，复用 `transactions` 表
- 后端新增 1 个聚合 API：`GET /api/statistics/daily-summary?month=2026-05&book_id=xxx`
  - 返回：`[{ date, total_income, total_expense, transaction_count }]`
- 前端日历组件选型：自行实现（轻量 CSS Grid），不引入重型第三方日历库
- 日视图交易明细走现有 `GET /api/transactions` 接口，加 `date` 参数筛选

**数据流**：
```
transactions 表 ──按天 GROUP BY──→ daily-summary API ──→ 日历网格渲染
                                    │
                                    └── 点击日期 ──→ GET /transactions?date=xxx ──→ 明细列表
```

**UI 参考**：类似 Google Calendar 月视图的简洁网格，去掉事件条，替换为金额数字。

### P1-2 批量操作 `PC`

**定位**：PC 端交易列表支持多选 + 批量编辑/删除，一次改动一批。

**痛点**：逐条修改效率低，PC 端天然适合多选操作。

**核心功能**：

| 功能 | 描述 |
|------|------|
| 多选交互 | 列表每行左侧复选框，表头全选，选中项底部浮现操作栏 |
| 批量改分类 | 选中交易统一更换分类 |
| 批量改类型 | 收入⇄支出互转 |
| 批量改日期 | 统一调整为指定日期 |
| 批量迁移账本 | 移入指定账本 |
| 批量删除 | 统一删除，走 ConfirmDialog 二次确认 |

**后端 API**：统一批量接口，一条 SQL 完成，**禁止循环调用**。

```
POST /api/transactions/batch
{
  "ids": ["uuid1", "uuid2", ...],
  "operation": "update_category" | "update_type" | "update_date" | "move_book" | "delete",
  "payload": {
    "category_id": "...",   // update_category
    "type": "expense",      // update_type
    "date": "2026-05-20",   // update_date
    "book_id": "..."        // move_book
  }
}
```

**技术边界**：
- 不新增表，后端单条 `UPDATE ... WHERE id IN (...)` 批量更新
- 跨页选择：前端维护 `selectedIds` Set，翻页不丢
- 批量删除统一走 `ConfirmDialog`

### P1-3 预算预警 `PC`

**定位**：仪表板集成预算消耗进度，超支主动提醒。

**痛点**：预算设了但形同虚设——只有打开预算页才能看到，没人会天天去看。

**核心功能**：

| 功能 | 描述 |
|------|------|
| 仪表板进度条 | 有预算的分类在仪表板顶部以横条显示消耗进度 |
| 颜色分级 | 绿(<70%) → 黄(70-90%) → 红(90-100%) → 爆炸红(>100%) |
| 超支 banner | 任意分类超过 90% 时，仪表板顶部浮现醒目提醒横幅 |
| 点击穿透 | 点击进度条直接跳转该分类的交易列表 |

**后端 API**：

```
GET /api/budgets/status?month=2026-05&book_id=xxx
→ [{ category_id, category_name, budget_amount, spent_amount, percentage, level: "safe"|"warning"|"danger"|"over" }]
```

**技术边界**：
- **不新增表**，跨表聚合 `budgets` + `transactions` 实时计算
- 预算额来自 `budgets` 表，消费额来自 `transactions` 按 category 求和
- banner 支持一键关闭（当天不再显示）

### P1-4 高级搜索 & 多条件筛选 `PC`

**定位**：交易记录页新增可展开的高级筛选面板，支持多条件组合过滤。

**痛点**：目前只能按分类和类型筛选，金额范围、日期范围、关键词搜索都不支持。

**核心功能**：

| 功能 | 描述 |
|------|------|
| 筛选面板 | 顶部可展开/收起，展开后显示多条件输入区 |
| 金额范围 | 最小金额 ~ 最大金额 |
| 日期范围 | 开始日期 ~ 结束日期 |
| 关键词搜索 | 模糊匹配备注字段 |
| 条件 Chip | 已激活的筛选条件以 Tag 形式展示，可单独 × 移除 |
| 条件联动 | 筛选条件变化实时请求后端，列表自动刷新 |

**后端改动**：扩展现有 `GET /api/transactions` 接口参数——

| 新增参数 | 类型 | 说明 |
|----------|------|------|
| `keyword` | string | 备注模糊搜索 |
| `min_amount` | number | 金额下限 |
| `max_amount` | number | 金额上限 |
| `date_from` | string | 开始日期 |
| `date_to` | string | 结束日期 |

**技术边界**：
- 复用现有 `GET /api/transactions`，不新增接口
- 不新增表，不存筛选历史

### P1-5 交易模板 `PC`

**定位**：侧边栏常驻快捷模板，点击一键记账，消灭重复录入。

**痛点**：午餐、通勤、咖啡——每天重复的交易每次都要重新填分类、金额、备注。

**使用流程**：

```
侧边栏「快捷模板」区
  ├── 📋 公司吃午饭        ← 点击
  ├── 🚇 地铁通勤
  └── ☕ 下午咖啡
         │
         ▼ 点击模板
  弹出记账浮窗（字段已预填）
  金额可修改 → 确认 → 一笔交易创建完成
```

**模板字段**：

| 字段 | 示例 | 说明 |
|------|------|------|
| 模板名称 | 公司吃午饭 | 显示在侧边栏 |
| 类型 | 支出 | income / expense |
| 金额 | 35.00 | 可留空，每次手动填 |
| 分类 | 餐饮 | 关联 category_id |
| 备注 | 在公司中午吃午饭，某某账单 | 支持预设文本 |
| 经纬度 | 31.2304, 121.4737 | 可选，复用地图位置 |
| 地址 | 上海市黄浦区xx路 | 可选 |
| 商户/POI | 某某食堂 | 可选，关联 poi_id |
| 默认账本 | 家庭账本 | 关联 book_id |
| 排序 | 1 | 侧边栏排列顺序 |

**数据表**（新增）：
```sql
CREATE TABLE transaction_templates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(50) NOT NULL,
  type VARCHAR(10) NOT NULL DEFAULT 'expense',
  amount NUMERIC(12,2),
  category_id UUID REFERENCES categories(id),
  note VARCHAR(200),
  latitude DOUBLE PRECISION,
  longitude DOUBLE PRECISION,
  location_name VARCHAR(100),
  poi_id VARCHAR(100),
  merchant_name VARCHAR(100),
  book_id UUID REFERENCES books(id),
  sort_order INT DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT now()
);
```

**后端 API**：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/templates` | 获取用户模板列表（按 sort_order 排序） |
| POST | `/api/templates` | 创建模板 |
| PUT | `/api/templates/:id` | 编辑模板 |
| DELETE | `/api/templates/:id` | 删除模板 |
| POST | `/api/templates/:id/execute` | 执行模板（创建交易 + 返回交易详情） |

**前端交互**：
- 侧边栏新增「快捷模板」区块，显示用户模板列表
- 点击模板 → 浮窗弹出，金额可修改 → 确认即创建交易 → toast 提示成功
- 模板管理入口：侧边栏底部「管理模板」→ 跳转模板管理页
- 模板管理页支持拖拽排序

**技术边界**：
- ⚠️ 新增 1 张表 `transaction_templates`
- 新增后端 `TemplatesModule`（module/controller/service/dto）
- 执行模板时在 service 层插入 `transactions`，无需前端组装

### P1-6 成员消费对比 `PC`

**定位**：报表页新增「成员对比」维度，可视化展示账本内各成员消费差异。

**痛点**：多人账本里成员只是个标签，看不到谁花了多少、花在哪。

**核心功能**：

| 功能 | 描述 |
|------|------|
| 支出占比环形图 | 各成员支出金额 + 占比，一眼看出谁是消费主力 |
| 分类对比柱状图 | 每个成员按 Top 5 分类并排展示，横向对比消费结构 |
| 月度支出矩阵 | 成员 × 月份表格，热力色标注高低 |
| 筛选联动 | 按账本、按月份范围切换，全图表联动刷新 |

**后端 API**：

```
GET /api/statistics/member-comparison?book_id=xxx&month=2026-05&month_to=2026-07
→ [{
    user_id, user_name,
    total_expense,
    categories: [{ category_name, category_icon, amount, percentage }]
  }]
```

**技术边界**：
- **不新增表**，`transactions` 已有 `user_id`，跨表关联 `users` + `categories`
- 报表页新增第 4 个 Tab：「成员对比」
- 前端复用 ECharts 环形图 + 柱状图
