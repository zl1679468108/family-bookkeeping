# 静记 - 前端 PC 端测试用例

## 测试用例说明

### 测试用例格式
每个测试用例包含以下要素：
- **用例编号**：唯一标识符
- **测试模块**：所属功能模块
- **测试场景**：测试的具体场景
- **前置条件**：执行测试前需要满足的条件
- **测试步骤**：详细的操作步骤
- **预期结果**：期望的测试结果
- **优先级**：P0（核心）、P1（重要）、P2（一般）

## 一、用户认证模块

### 1.1 登录页面

#### 用例 TC-AUTH-001：正常登录
- **测试模块**：用户认证 - 登录
- **测试场景**：使用正确的邮箱和密码登录
- **前置条件**：用户已注册
- **测试步骤**：
  1. 打开登录页面 `/login`
  2. 输入已注册的邮箱地址
  3. 输入正确的密码
  4. 点击"登录"按钮
- **预期结果**：
  - 登录成功，页面跳转至首页 `/`
  - 顶部导航栏显示用户信息
  - LocalStorage 中保存认证 token
- **优先级**：P0

#### 用例 TC-AUTH-002：登录 - 邮箱格式验证
- **测试模块**：用户认证 - 登录
- **测试场景**：输入无效邮箱格式
- **前置条件**：无
- **测试步骤**：
  1. 打开登录页面
  2. 输入无效邮箱（如 `invalid-email` 或空值）
  3. 输入密码
  4. 点击"登录"按钮
- **预期结果**：
  - 浏览器原生验证阻止表单提交
  - 显示"请输入有效的邮箱地址"提示
  - 不发起登录请求
- **优先级**：P1

#### 用例 TC-AUTH-003：登录 - 密码错误
- **测试模块**：用户认证 - 登录
- **测试场景**：输入错误密码
- **前置条件**：用户已注册
- **测试步骤**：
  1. 打开登录页面
  2. 输入已注册的邮箱
  3. 输入错误的密码
  4. 点击"登录"按钮
- **预期结果**：
  - 显示错误提示通知（Toast）
  - 停留在登录页面
  - 密码框内容不清空
  - 登录按钮恢复可点击状态
- **优先级**：P1

#### 用例 TC-AUTH-004：登录 - 加载状态
- **测试模块**：用户认证 - 登录
- **测试场景**：登录请求过程中的 UI 状态
- **前置条件**：无
- **测试步骤**：
  1. 打开登录页面
  2. 输入邮箱和密码
  3. 点击"登录"按钮
  4. 观察登录请求过程中的按钮状态
- **预期结果**：
  - 按钮文字变为"登录中..."
  - 按钮变为 disabled 状态
  - 防止重复提交
  - 请求完成后按钮恢复
- **优先级**：P2

#### 用例 TC-AUTH-005：登录 - 记住登录状态
- **测试模块**：用户认证 - 登录
- **测试场景**：刷新页面后保持登录状态
- **前置条件**：用户已登录
- **测试步骤**：
  1. 登录后进入首页
  2. 刷新浏览器页面
  3. 检查登录状态
- **预期结果**：
  - 用户保持登录状态
  - 不需要重新登录
  - 可以正常访问需要认证的页面
- **优先级**：P0

#### 用例 TC-AUTH-006：登录 - 未登录访问需认证页面
- **测试模块**：用户认证 - 登录
- **测试场景**：未登录时访问需要认证的页面
- **前置条件**：用户未登录或 token 过期
- **测试步骤**：
  1. 清除登录状态或直接访问 `/add`
  2. 观察页面跳转
- **预期结果**：
  - 自动重定向到登录页 `/login`
  - URL 携带 redirect 参数（如 `/login?redirect=/add`）
  - 登录后自动跳转回原页面
- **优先级**：P0

#### 用例 TC-AUTH-007：登录 - 链接导航
- **测试模块**：用户认证 - 登录
- **测试场景**：点击忘记密码和注册链接
- **前置条件**：无
- **测试步骤**：
  1. 打开登录页面
  2. 点击"忘记密码？"链接
  3. 返回登录页，点击"注册新账户"链接
- **预期结果**：
  - "忘记密码？"跳转到 `/forgot-password`
  - "注册新账户"跳转到 `/register`
  - 链接样式正常（hover 效果）
- **优先级**：P2

### 1.2 注册页面

#### 用例 TC-AUTH-010：正常注册
- **测试模块**：用户认证 - 注册
- **测试场景**：使用新邮箱注册账户
- **前置条件**：无
- **测试步骤**：
  1. 打开注册页面 `/register`
  2. 输入有效的邮箱地址
  3. 输入符合要求的密码（6 位以上）
  4. 输入确认密码（与密码一致）
  5. 点击"注册"按钮
- **预期结果**：
  - 注册成功
  - 自动登录并跳转到首页
  - 显示成功提示通知
- **优先级**：P0

#### 用例 TC-AUTH-011：注册 - 密码长度验证
- **测试模块**：用户认证 - 注册
- **测试场景**：密码少于 6 位
- **前置条件**：无
- **测试步骤**：
  1. 打开注册页面
  2. 输入邮箱
  3. 输入少于 6 位的密码（如 `12345`）
  4. 输入确认密码
  5. 点击"注册"按钮
- **预期结果**：
  - 浏览器验证阻止提交或显示错误提示
  - 提示"密码至少 6 位"
  - 不发起注册请求
- **优先级**：P1

#### 用例 TC-AUTH-012：注册 - 密码不一致
- **测试模块**：用户认证 - 注册
- **测试场景**：密码和确认密码不一致
- **前置条件**：无
- **测试步骤**：
  1. 打开注册页面
  2. 输入邮箱
  3. 输入密码（如 `123456`）
  4. 输入不同的确认密码（如 `654321`）
  5. 点击"注册"按钮
- **预期结果**：
  - 显示"两次输入的密码不一致"提示
  - 不发起注册请求
  - 确认密码框可能被清空或高亮
- **优先级**：P1

#### 用例 TC-AUTH-013：注册 - 邮箱已存在
- **测试模块**：用户认证 - 注册
- **测试场景**：使用已注册的邮箱注册
- **前置条件**：该邮箱已被注册
- **测试步骤**：
  1. 打开注册页面
  2. 输入已存在的邮箱
  3. 输入密码和确认密码
  4. 点击"注册"按钮
- **预期结果**：
  - 显示错误提示"该邮箱已被注册"
  - 停留在注册页面
  - 注册按钮恢复可点击状态
- **优先级**：P1

#### 用例 TC-AUTH-014：注册 - 表单自动填充
- **测试模块**：用户认证 - 注册
- **测试场景**：浏览器自动填充表单
- **前置条件**：浏览器保存了该网站的表单数据
- **测试步骤**：
  1. 打开注册页面
  2. 观察浏览器是否自动填充邮箱和密码
- **预期结果**：
  - 浏览器可以正常自动填充
  - 填充后表单字段有正确样式
  - 不影响手动修改
- **优先级**：P2
