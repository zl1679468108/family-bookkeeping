| 属性 | 说明 |

---

## 2. 产品定义

### 2.1 产品目标

1. **消费空间可视**：将抽象的交易数据落到地图上，让用户直观看到"钱花在哪儿了"——消费密集区域一目了然
2. **商户消费洞察**：聚合单商户维度的消费数据（总金额、频次、趋势），帮助用户识别"高频高消费"商户，辅助消费决策
3. **基础能力沉淀**：建立位置数据基础设施（经纬度存储、POI 搜索、地图组件），为后续家庭位置、资产管理等功能铺路

### 2.2 用户故事

- **US-1**：作为记账用户，我希望能在地图上看到所有消费点的分布，以便直观了解我的消费活动在空间上的分布规律。
- **US-2**：作为记账用户，我希望通过热力图一眼识别消费密集区域，以便发现哪些商圈/地段是我消费最集中的地方。
- **US-3**：作为记账用户，我希望能按时间、分类、金额筛选地图上的消费点，以便聚焦分析特定类型的消费行为。
- **US-4**：作为记账用户，我希望能查看某个商户下的消费汇总（总金额、次数、趋势），以便了解在该商户的消费习惯。
- **US-5**：作为记账用户，我希望能搜索附近商户并查看消费记录，以便回顾在特定区域的消费情况。

## 3. 技术规范

### 3.1 需求池

#### P0 — 本迭代交付

| 编号 | 需求 | 详细说明 |
| :--- | :--- | :--- |
| **P0-1** | 数据库扩展 — transactions 增加位置字段 | 新增 `latitude`、`longitude`、`location_name`、`poi_id` 四个字段，均为可选（保持向后兼容） |
| **P0-2** | 记账页集成位置选择 | 在 `/add` 页面增加「添加位置」入口，点击后弹出地图选点组件（高德地图），支持：拖拽定位、搜索地址、点击地图选点；确认后自动填充经纬度 + 地址名称 + POI ID |
| **P0-3** | 地图主页 `/map` — 消费点标记 | 地图页面默认展示当前用户所有带位置信息的交易记录，按分类使用不同颜色的 Marker 标记；点击 Marker 弹出信息窗（分类图标 + 金额 + 日期 + 备注摘要） |
| **P0-4** | 地图主页 `/map` — 筛选栏 | 地图页面顶部筛选栏，支持：时间范围（DateRangeFilter 复用）、分类多选（复用分类接口）、金额范围（最小/最大输入框）；筛选条件变化时实时更新地图标记 |
| **P0-5** | 地图主页 `/map` — 热力图图层 | 在标记点基础上叠加热力图图层（高德 HeatMap），以颜色深浅表示消费密集程度；提供「标记/热力图」切换按钮 |
| **P0-6** | 商户地图视图 | 以商户（location_name + poi_id 聚合）为维度展示：地图上按消费总金额大小显示不同大小的圆点；点击圆点弹出商户卡片（商户名称、消费总金额、消费次数、最近消费日期、金额趋势迷你图） |
| **P0-7** | 商户列表视图 | 地图页面提供「地图/列表」切换；列表模式按消费总金额降序排列商户，每行显示：商户名称、POI 标签、消费总金额、消费次数、最近消费日期；支持按金额/次数排序切换 |
| **P0-8** | 附近商户搜索 | 地图页面搜索框：输入关键词 → 调用高德 POI 搜索 API → 展示搜索结果列表 → 点击结果定位到地图对应位置；搜索结果与已有消费记录交叉标记（有记录 vs 无记录用不同图标） |
| **P0-9** | 侧边栏导航入口 | Sidebar 新增「消费地图」导航项，图标使用地图相关 SVG，路由 `/map` |
| **P0-10** | 后端 API — 位置查询接口 | NestJS 新增 `GET /map/transactions` 接口，支持筛选参数（时间/分类/金额范围/经纬度范围），返回带位置信息的交易列表；`GET /map/merchants` 接口返回按商户聚合的消费汇总 |

#### 交互流程

1. **入口**：侧边栏点击「消费地图」→ 进入 `/map`
2. **默认视图**：地图展示所有消费标记点，右侧或底部浮动面板显示统计摘要（总消费点数、总金额、覆盖商户数）
3. **筛选**：顶部筛选栏修改条件 → 地图标记实时更新
4. **视图切换**：
   - 标记模式：按分类颜色显示独立 Marker
   - 热力图模式：聚合展示消费密度
   - 商户列表模式：按消费金额排序的商户卡片列表
5. **商户搜索**：搜索框输入 → POI 联想 → 选择结果 → 地图定位 + 已有消费标记高亮
6. **商户详情**：点击商户圆点/列表项 → 弹出商户详情卡片（总金额、次数、趋势、最近消费列表）
7. **记账联动**：商户详情卡片提供「记一笔」快捷入口 → 跳转 `/add` 并预填位置信息

#### 关键交互规则

- 地图初始中心点：用户最近消费点聚合中心，无消费数据时默认北京
- 缩放级别联动：地图缩放时动态调整聚合粒度（高缩放显示单个点，低缩放合并邻近点）
- 分类颜色映射：复用 ECharts 统计报表中的分类颜色体系，保持视觉一致性

### 3.3 数据模型变更

#### transactions 表扩展

```sql
-- 新增位置相关字段
ALTER TABLE transactions
  ADD COLUMN IF NOT EXISTS latitude       DECIMAL(10, 7),
  ADD COLUMN IF NOT EXISTS longitude      DECIMAL(10, 7),
  ADD COLUMN IF NOT EXISTS location_name  VARCHAR(200),
  ADD COLUMN IF NOT EXISTS poi_id         VARCHAR(100);

-- 新增索引
CREATE INDEX IF NOT EXISTS idx_transactions_location 
  ON transactions(latitude, longitude) 
  WHERE latitude IS NOT NULL AND longitude IS NOT NULL;

COMMENT ON COLUMN transactions.latitude      IS '纬度，范围 -90 ~ 90';
COMMENT ON COLUMN transactions.longitude     IS '经度，范围 -180 ~ 180';
COMMENT ON COLUMN transactions.location_name IS '地点名称/地址描述';
COMMENT ON COLUMN transactions.poi_id        IS '高德地图 POI ID';
```

#### 后端 DTO 扩展

- `CreateTransactionDto` 新增可选字段：`latitude?`, `longitude?`, `locationName?`, `poiId?`
- `UpdateTransactionDto` 同上
- 新增 `MapTransactionQueryDto`：时间范围、分类数组、金额范围、经纬度范围（用于地图视口内查询）
- 新增 `MerchantSummaryDto`：商户名、POI ID、总金额、总次数、最近消费日期

### 3.4 技术选型说明

| 选型 | 决策 | 理由 |
| :--- | :--- | :--- |
| 地图 SDK | 高德地图 JS API 2.0 | 免费额度 30 万次/天，POI 数据最全，热力图原生支持 |
| React 封装 | `@uiw/react-amap` | 社区成熟度高，TypeScript 支持好，API 符合 React 习惯 |
| 热力图 | 高德 HeatMap 插件（AMap.HeatMap） | 原生支持，无需额外引入第三方库 |
| POI 搜索 | 高德 PlaceSearch API（JS API 内置） | 搜索 + 联想一次搞定，无需后端代理 |
