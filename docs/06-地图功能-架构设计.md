## 2. 设计决策

### 2.1 后端：新建 MapModule vs 扩展 TransactionModule

**决策：新建独立 MapModule**

理由：
- 地图接口有独立的查询逻辑（需要按 book_id 聚合、按 POI 分组）
- 不与现有 Transaction CRUD 耦合，职责清晰
- 遵循现有模块模式（statistics 也是独立模块做聚合查询）
- 未来 P1/P2 新增 assets、trips 时可扩展同一模块

### 2.2 前端：组件拆分

```
pages/Map.tsx                    # 页面容器，管理全局状态（筛选条件、视图模式）
  ├── components/MapHeader.tsx   # 筛选栏（复用 DateRangeFilter + 分类多选 + 金额范围）
  ├── components/MapCanvas.tsx   # 地图画布（高德地图实例 + 图层管理）
  │   ├── MarkerLayer            # 消费点标记（内联在 MapCanvas 中）
  │   ├── HeatMapLayer           # 热力图图层（内联在 MapCanvas 中）
  │   └── POISearchBar           # POI 搜索（内联在 MapCanvas 中）
  ├── components/MerchantCard.tsx # 商户卡片弹窗
  └── components/MerchantList.tsx # 商户列表视图（地图/列表切换）
```

### 2.3 数据流

```
用户操作筛选栏 → MapHeader onChange → Map.tsx 更新 filter state
  → react-query queryKey 变化 → 自动 refetch
  → mapApi.fetchMapTransactions(filters) → GET /api/map/transactions
  → MapCanvas 接收 data → 渲染 Marker/HeatMap

用户切换视图 → Map.tsx viewMode state 变化
  → 条件渲染 MapCanvas 或 MerchantList

商户列表 → mapApi.fetchMerchants(filters) → GET /api/map/merchants
  → MerchantList 展示

POI 搜索 → 前端直接调用 AMap.PlaceSearch → 展示搜索结果
  → 与已有的 transactions location 交叉对比（前端本地匹配 poi_id）
```

### 2.4 book_id 隔离

- 前端：`request<T>()` 在 `requiresAuth: true` 时自动从 localStorage 读 `current_book_id` 并附加 `x-book-id` header
- 后端：`@BookId()` 装饰器从 header 提取，传入 Service → Supabase 查询 `.eq('book_id', bookId)`
- 无需额外处理，沿袭现有 `api.ts` 拦截器机制

## 3. 后端实现细节

### 3.1 新建文件清单

```
backend/src/map/

  ├── map.service.ts         # 业务逻辑
  └── dto/

```

### 3.2 map.module.ts

```typescript
@Module({
  imports: [SupabaseModule, AuthModule],
  controllers: [MapController],
  providers: [MapService],
})
export class MapModule {}
```

在 `app.module.ts` imports 数组中追加 `MapModule`。

### 3.3 map.controller.ts

| 路由 | 方法 | 说明 | Guards |
|------|------|------|--------|
| `GET /api/map/transactions` | `getMapTransactions` | 返回带位置信息的交易列表 | TokenAuthGuard |
| `GET /api/map/merchants` | `getMerchantSummary` | 返回按 POI 聚合的商户消费汇总 | TokenAuthGuard |

参数提取：`@CurrentUser('id')`, `@BookId()`, `@Query()`（通过 DTO 自动验证）

### 3.4 map.service.ts

**getTransactionsWithLocation(userId, bookId, query):**
- Supabase 查询 transactions 表，条件：`latitude IS NOT NULL AND longitude IS NOT NULL`
- 支持过滤：`startDate/endDate`、`categories[]`、`minAmount/maxAmount`、`type`
- 按 `book_id = bookId` 过滤（bookId 有效时）
- 返回字段：id, type, category, amount, date, description, latitude, longitude, location_name, poi_id

**getMerchantSummary(userId, bookId, query):**
- 按 `poi_id + location_name` 分组聚合
- 聚合维度：总金额(SUM)、总次数(COUNT)、最近日期(MAX(date))
- 过滤条件同上
- 返回按总金额降序排列

### 3.5 DTO — map-query.dto.ts

```typescript
export class MapTransactionsQueryDto {
  @IsOptional() @IsString()
  startDate?: string;       // YYYY-MM-DD
  @IsOptional() @IsString()
  endDate?: string;         // YYYY-MM-DD
  @IsOptional() @IsString()
  type?: 'income' | 'expense';
  @IsOptional() @IsString()
  categories?: string;      // 逗号分隔，如 "food,transport"
  @IsOptional() @Type(() => Number) @IsNumber() @Min(0)
  minAmount?: number;
  @IsOptional() @Type(() => Number) @IsNumber() @Min(0)
  maxAmount?: number;
  @IsOptional() @Type(() => Number) @IsNumber()
  swLng?: number;           // 视口西南经度（预留，P0 可能不用）
  @IsOptional() @Type(() => Number) @IsNumber()
  swLat?: number;
  @IsOptional() @Type(() => Number) @IsNumber()
  neLng?: number;
  @IsOptional() @Type(() => Number) @IsNumber()
  neLat?: number;
}
```

### 4.3 API 服务 — services/mapApi.ts

```typescript
import { request } from './api';
import type { MapTransaction, MerchantSummary, MapFilters } from '../types/map';

export const fetchMapTransactions = (filters: MapFilters): Promise<MapTransaction[]> => {
  const params = new URLSearchParams();
  if (filters.startDate) params.append('startDate', filters.startDate);
  if (filters.endDate) params.append('endDate', filters.endDate);
  if (filters.type) params.append('type', filters.type);
  if (filters.categories?.length) params.append('categories', filters.categories.join(','));
  if (filters.minAmount != null) params.append('minAmount', String(filters.minAmount));
  if (filters.maxAmount != null) params.append('maxAmount', String(filters.maxAmount));
  
  return request<MapTransaction[]>(`/map/transactions?${params}`, { requiresAuth: true });
};

export const fetchMerchantSummary = (filters: MapFilters): Promise<MerchantSummary[]> => {
  const params = new URLSearchParams();
  if (filters.startDate) params.append('startDate', filters.startDate);
  if (filters.endDate) params.append('endDate', filters.endDate);
  
  return request<MerchantSummary[]>(`/map/merchants?${params}`, { requiresAuth: true });
};
```

### 5.1 SQL（需执行）

```sql
ALTER TABLE transactions
  ADD COLUMN IF NOT EXISTS latitude       DECIMAL(10, 7),
  ADD COLUMN IF NOT EXISTS longitude      DECIMAL(10, 7),
  ADD COLUMN IF NOT EXISTS location_name  VARCHAR(200),
  ADD COLUMN IF NOT EXISTS poi_id         VARCHAR(100);

CREATE INDEX IF NOT EXISTS idx_transactions_location 
  ON transactions(latitude, longitude) 
  WHERE latitude IS NOT NULL AND longitude IS NOT NULL;
```

## 6. 任务拆解

按依赖关系排序，共 **10 个任务**：

| # | 任务 | 涉及层 | 依赖 | 产出 |
|---|------|--------|------|------|
| T1 | P0-1 数据库扩展 | DB | 无 | 执行 SQL，更新 database-init.sql |
| T2 | P0-10 后端 Map API | 后端 | T1 | MapModule (4 文件) + 扩展 TransactionModule |
| T3 | P0-9 导航入口 + 路由 | 前端 | 无 | 修改路由、Sidebar |
| T4 | P0-3 消费点标记 | 前端 | T2, T3 | Map.tsx + MapCanvas + mapApi.ts + 类型 |
| T5 | P0-2 记账页位置选择 | 前端 | T3 | LocationPicker 组件 + 修改 AddTransaction |
| T6 | P0-5 热力图图层 | 前端 | T4 | 在 MapCanvas 中增加 HeatMapLayer |
| T7 | P0-4 地图筛选栏 | 前端 | T4 | MapHeader 组件 |
| T8 | P0-6 商户地图视图 | 前端 | T4 | MerchantCard 组件 |
| T9 | P0-7 商户列表视图 | 前端 | T4 | MerchantList 组件 |
| T10 | P0-8 附近商户搜索 | 前端 | T4 | POISearchBar（在 MapCanvas 内） |

### 执行顺序

```
阶段1 (并行): T1, T3
阶段2 (依赖T1): T2
阶段3 (依赖T2+T3): T4 → T5, T6, T7, T8, T9, T10 (T5-T10 可部分并行)
```

### 建议执行策略

**第一批**：T1 + T2 + T3（基础设施，1-2 轮对话）
→ 数据库就绪 + 后端 API 跑通 + 页面入口可见

**第二批**：T4 + T5（核心功能，2-3 轮对话）
→ 地图能展示消费点 + 记账能选位置

**第三批**：T6 + T7 + T8 + T9 + T10（增强功能，2-3 轮对话）
→ 热力图 + 筛选 + 商户视图 + POI 搜索

## 7. 风险 & 注意事项

| 风险 | 应对 |
|------|------|
| `@uiw/react-amap` 版本兼容性 | 先安装确认可用，不行就退回到直接用高德 JS API Loader |
| 高德 API Key 申请 | 需要到高德开放平台注册应用，获取 Web 端 Key |
| 热力图性能 | 消费点 > 1000 时考虑前端聚合后再渲染 |
| 移动端地图体验 | 地图页面优先考虑 PC 端，移动端后续优化 |
