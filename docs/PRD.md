## 1. 产品定位

<a id="1-product-positioning"></a>

静记是一款**家庭/团队协作记账工具**，支持多账本、多成员共享，通过数据可视化帮助用户掌握家庭财务状况。

**核心价值主张**:
- 多账本管理——家庭、旅行、项目账本独立核算
- 成员协作——邀请家人/朋友共同记账，实时查看消费分布
- 数据可视化——趋势图、分类占比、成员对比，一目了然
- 地图洞察——基于地理位置的消费分析与成员位置共享

**竞品定位**: 介于个人记账应用（随手记、挖财）和专业财务软件之间，轻量级、开箱即用、支持家庭协作。

## 2. 用户画像

<a id="2-user-persona"></a>

### 主要用户群体
- **家庭用户**，需要共同管理家庭收支
- **个人用户**，需要分类记账和预算管理
- **情侣/室友**，需要共享账本协作记账

### 使用场景
| 场景 | 描述 |
|------|------|
| 日常记账 | 快速记录每笔收入/支出，支持模板一键填充 |
| 家庭协作 | 多人共享账本，实时查看家庭财务状况 |
| 预算控制 | 设置月度预算，超支预警，控制消费 |
| 数据分析 | 通过图表了解消费结构，优化理财习惯 |
| 位置追踪 | 记录消费地点，查看家庭成员位置 |

## 4. 功能详细需求

<a id="4-feature-details"></a>

### 4.1 用户认证

#### 4.1.1 邮箱密码登录
- 用户使用邮箱和密码登录
- 登录成功进入首页，失败显示错误提示
- 账号不存在/密码错误时给出明确提示
- 登录态持久化，下次打开应用自动登录

#### 4.1.2 邮箱密码注册
- 新用户通过邮箱和密码注册
- 注册成功自动登录，失败显示错误提示
- 邮箱已注册时提示
- 需要图形验证码防机器人

#### 4.1.3 密码重置
- 方式一：输入邮箱 → 发送重置链接 → 点击链接重置密码
- 方式二：输入邮箱 → 发送验证码 → 输入验证码重置密码

#### 4.1.4 切换账号
- 支持多账号切换，无需重新登录
- 切换后自动刷新当前账本数据

#### 4.1.5 登出
- 使用应用内小弹窗二次确认
- 清除本地 token，跳转到登录页

#### 4.1.6 路由守卫
- 未登录自动跳转到登录页
- 已登录访问认证页面自动跳转到首页

### 4.2 仪表板

**路由**：`/` (PC) / 首页 Tab (小程序)

#### 4.2.1 财务概览
- 展示当前账户余额（收入 - 支出）
- 展示累计总收入和总支出
- 本月数据环比变化

#### 4.2.2 快捷操作

- 支持下拉刷新数据

### 4.3 交易记录

**路由**：`/transactions` (PC) / 交易 Tab (小程序)

#### 4.3.1 交易列表
- 展示所有交易记录
- 每条记录显示：分类图标、描述、金额、日期、收据标识
- 支持分页加载

#### 4.3.2 筛选功能
- **类型筛选**：全部/收入/支出
- **分类筛选**：按分类筛选交易
- **时间范围**：按日期区间筛选
- **关键词搜索**：按描述搜索
- **金额范围**：按金额区间筛选

#### 4.3.3 排序
- 按金额或日期排序
- 支持升序/降序

#### 4.3.4 批量操作
- 进入批量模式，支持全选
- 批量删除/移动账本

#### 4.3.5 创建/编辑交易
- **必填字段**：金额、类型（收入/支出）、分类
- **选填字段**：描述、日期、位置、收据图片
- 支持模板快速填充

#### 4.3.6 收据上传
- 上传收据图片（jpg/png/webp）
- 前端压缩至 ≤300KB
- 支持查看/替换/删除收据

## 8. 技术约束

<a id="8-technical-constraints"></a>

### 8.1 项目架构

```
family-bookkeeping/
├── frontend/              # PC Web 前端（React 18 + Vite + TypeScript）
├── shared-types/          # 三端共享 TypeScript 类型包
├── backend/               # 后端服务（NestJS 10 + Supabase）
├── taro/                  # 微信小程序（Taro 4 + React）
├── config/                # 配置文件
├── scripts/               # 部署脚本
└── docs/                  # 文档目录
```

**三端独立架构**，共享同一 Supabase 数据库，非 monorepo。

### 8.2 数据库约束
- 所有表使用 `jj_` 前缀
- 12 张核心表：users、user_sessions、password_resets、categories、books、book_members、transactions、budgets、transaction_templates、member_locations、book_invitations、custom_icons
- DDL 变更需手动在 Supabase SQL Editor 执行

### 8.3 认证机制
- 自定义双 Token Session（非 JWT）：Access Token（~2h）+ Refresh Token（~14d）
- Token：64 字符 hex，SHA-256 hash 存入 `user_sessions` 表
- 客户端用 `Authorization: Bearer <token>` 传递

### 8.4 API 约束
- 所有响应被 `ResponseInterceptor` 统一包装：`{ success, message, data }`
- 时间戳自动转换为北京时间 `YYYY-MM-DD HH:mm:ss.SSS`
- 前端 `request<T>()` 函数自动解包，直接返回 `data`

### 8.5 性能约束
- 列表数据分页加载
- 搜索使用 300ms 防抖
- 图片上传前压缩（≤300KB）
- React Query 缓存：staleTime 5 分钟

### 8.6 部署约束
- 平台：腾讯云 CVM（上海二区）+ Nginx + PM2
- 后端：Docker 容器部署于 CVM，Nginx 反代 `zlspace.site/api`
- 前端：构建产物托管于 CVM Nginx 静态目录
- 无 CI/CD，手动或脚本部署（`scripts/deploy-cvm.sh`）
